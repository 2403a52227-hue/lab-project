Behavioral design patterns

BookNest demonstrates three patterns from the SESD assignment.

◉
1. Observer Pattern

Purpose: define a one-to-many dependency so subscribers receive updates when a subject changes. Here, readers are notified when book availability changes.

Classes: Book, StudentNotification
⇄
2. Strategy Pattern

Purpose: encapsulate interchangeable algorithms. Here, the fine calculator can use standard, student, or no-fine policies at runtime.

Classes: FineCalculator, StandardFineStrategy, StudentFineStrategy, NoFineStrategy
↶
3. Command Pattern

Purpose: encapsulate a request as an object. Here, borrow and return actions can be recorded and the last action can be undone.

Classes: BorrowBookCommand, ReturnBookCommand, CommandManager
